## Pattern rules

### SE_NO_CONTRACTIONS: No contractions

Write the words in full. No contractions.

- Wrong: You don't need this file.
- Right: You do not need this file.

### SE_NO_SEMICOLON: No semicolons

Write two sentences, or name the relation.

- Wrong: Start the tool; then read the log.
- Right: Start the tool. Then read the log.

### SE_NO_EMDASH: No em-dashes

Write two sentences, or use a comma.

- Wrong: The tool is fast—it also works.
- Right: The tool is fast. It also works.

### SE_MODAL_RESTRICTED: Only can, will, must

Use can, will, or must. State the requirement exactly.

- Wrong: You should restart the service.
- Right: You must restart the service.

### SE_ACTIVE_VOICE: Active voice

Use the active voice. Say who does the action.

- Wrong: The log was written by the worker.
- Right: The worker wrote the log.

### SE_PRESENT_PERFECT: Simple tenses only

Use the simple past. Say when it happened.

- Wrong: The job has completed.
- Right: The job completed.

### SE_ING_AFTER_COMMA: No -ing after a comma

Start a new sentence instead of the -ing phrase.

- Wrong: The tool runs, making it easy.
- Right: The tool runs. It is easy.

### SE_KEEP_THAT: make sure that

Write "make sure that".

- Wrong: Make sure the file exists.
- Right: Make sure that the file exists.

### SE_CONDITION_FIRST: Condition before command

Put the condition first: "If the build fails, read the log."

- Wrong: Read the log if the build fails.
- Right: If the build fails, read the log.

### SE_SLOP_LEVERAGE: use, not leverage

- Right: Use the registry file.

## Counting rules

These rules run in Ruby on Markdown text. Code comments do not use
them. Procedural text is a list item. Descriptive text is every
other paragraph.

### SE_SENTENCE_TOO_LONG

A sentence with more than 20 words in
procedural text, or more than 25 words
in descriptive text.

### SE_PARAGRAPH_TOO_LONG

A paragraph with more than 6
sentences in descriptive text.
